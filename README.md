# Philosophers

## 📄 Description

This project, inspired by the famous "Dining Philosophers Problem" introduces the fundamental concepts of concurrent programming using threads. Philosophers explores how to create and manage threads, mutexes for synchronization. Understanding critical concepts like deadlocks and dataraces and how o avoid them was necessary to succesfully develop this project.

### What is Dining Philosophers Problem?

The Dining Philosophers Problem is a fundamental synchronization problem often used in concurrent algorithm design to illustrate synchronization issues and techniques for resolving them. In this problem, a number of philosophers sit at a round table with a bowl of spaghetti in the center. Between each pair of philosophers is a single fork. Each philosopher alternates between eating, sleeping and thinking:

- **Eating**: The philosopher is required to have a fork in each hand to be allowed to eat.
- **Sleeping**: After eating, the philosopher rests
- **Thinking**: The philosopher contemplates life if there are no forks available for him to eat.

### Project Goals

- Understand the basics of threading and concurrent programming
- Learn how to create and manage multiple threads simultaneously
- Master mutex usage for protecting shared resources
- Identify and prevent data races and deadlock situations

## 📝 Instructions

The project must be compiled using `cc` with the following flags:

```bash
-Wall -Wextra -Werror -pthread
```

The included `Makefile` already compiles the program correctly. Simply run:

```bash
make
```

You are also able to run these `make` commands below:

```bash
make clean
make fclean
make re
```

`clean` = is used to remove build files (object files .o and tmp binary files) generated by the compilation process. 

`fclean` = is used to remove all build files, including the executable.

`re` = is used to make a fresh and clean build by deleting previous files and artifacts that might cause issues, like leftover configuration files. 

### Execution

```bash
./philo 4 800 200 200 [5]
```

This command creates 4 philosophers, each one with: 

`time_to_die` = 800ms — max time given for them to die.

`time_to_eat` = 200ms — time given for them to eat.

`time_to_sleep` = 200ms — time given for them to sleep.

`times_each_philo_must_eat` **`OPTIONAL VALUE`** = 5 — minimum times each philo needs to eat for program to finish.

During the execution, the program will show this in the standard output the state of each philosopher: 

```bash
0     1  is thinking
0     1  has taken a fork
0     1  has taken a fork
0     1  is eating
200   1  is sleeping
400   1  is thinking
...
```

The simulation will result in one of three outcomes:

1. **A philosopher dies**: If the timing parameters make it impossible to keep all philosophers alive;
2. **Simulation completes successfully**: If the optional `times_each_philo_must_eat` argument is provided and all philosophers eat the required number of times;
3. **Infinite simulation**: If the parameters allow all philosophers to eat indefinitely without dying.

## How to debug

You can use `valgrind ./philo` to run and detect memory access errors and leaks. It identifies critical issues such as reading uninitialized memory, accessing unallocated memory, array out-of-bounds errors, and memory leaks where allocated memory is never freed. You can also run with additonal flags such as `--leak-check=full` for detailed reports.

```bash
valgrind --leak-check=full ./philo 2 410 200 200
```
